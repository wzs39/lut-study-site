本节定位

写程序的时间，大半花在找错上。这一讲不教新功能，而是教「怎么看懂报错、怎么让它别崩」。它是整门课从「会写」走向「写得能跑」的分水岭，也是期末机考最容易丢分的地方——不是不会写，而是报错看不懂。

内容上与前面每一讲都相关：语法错误对应第 3–5 讲的缩进与冒号，运行时错误对应第 3 讲的类型、第 8 讲的下标、第 9 讲的文件，逻辑错误对应第 4 讲的 elif 顺序与第 5 讲的边界。

学完本讲你应当能够：

  • 把错误分成语法、运行时、逻辑三类，并说出各自能否被 try 捕获
  • 认识 TypeError、NameError、IndexError、ValueError、ZeroDivisionError、FileNotFoundError 的触发条件
  • 从 traceback 的最后一行读出异常类型，再顺着调用栈找到自己写的行
  • 写出 try/except，用 as e 拿到异常对象并打印
  • 用多 except 按类型分别处理，并解释顺序为什么重要
  • 写出「输入不合法就重试」的循环，直到拿到合法值

一、错误是编程的一部分

课件开门见山：错误（bug）不可避免，识别与修复它是程序员的核心技能（Errors p2）。错误大致分三类，处理方式完全不同：

类型发生时机典型例子能否被 try 捕获
语法错误 syntax error写代码时/运行前漏冒号、缩进错、括号不配对、10 = x、把关键字当变量名不能——程序根本没跑起来
运行时错误 runtime error执行到那一行时除零、类型不匹配、变量未定义、下标越界能——这是 try/except 处理的对象
逻辑错误 logical error程序跑完、结果不对条件写反、循环少一次、初值错、用错运算符不能——不报错，只能靠测试发现

这三类的排查顺序不同：语法错误看报错行号；运行时错误看异常类型与调用栈；逻辑错误没有报错，只能靠「输入 → 期望输出 → 实际输出」的对照。

二、语法错误：解释器根本读不懂

课件列的五个典型（Errors p3）几乎覆盖了所有语法错误：

if x > 5          # 漏冒号
    print("big")

if 5 > 2:
print("no indent")    # 缩进错

print("a"             # 括号不配对

10 = x                 # 赋值目标不能是字面量

def = "house"          # 关键字不能当变量名

它们都在程序运行之前就被 Python 拦下，报错信息里带文件、行号与一个 ^ 指向大致位置。注意行号常常「晚一行」——解释器要到下一行才发现上一行没收尾，所以真正的错误往往在报错行的上一行。

  File "demo.py", line 3
    print("a"
         ^
SyntaxError: '(' was never closed

三、运行时错误：能跑，但跑到某行就崩

课件列了四种最常见（Errors p5）：除零 10 / 0、类型错误 "hello" + 5、变量未定义、下标越界。下面这张表把异常名与触发条件对齐（Run-time_errors p2–p10）：

异常触发条件最小例子
TypeError对不合适的类型做运算"hello" + 5
NameError名字（变量/函数）不存在print(total)（从未赋值）
IndexError下标越界[1, 2][5]
AttributeError对象没有这个属性/方法"abc".push("d")
ValueError类型对但值不合适int("abc")
ZeroDivisionError除零或对零取模10 / 0
FileNotFoundError文件/目录不存在open("nope.txt")
ImportError模块找不到或名字不在模块里import datetimes

记住两个容易混的：ValueError 是「类型对了、值不对」（int("abc") 的输入确实是字符串），TypeError 是「类型就不对」（int([1,2])）。

四、读懂 traceback

报错时 Python 打印的整段叫调用栈回溯（traceback）。读法只有一条：先看最后一行（异常类型 + 消息），再往上找自己写的文件与行号。

def divide(x, y):
    return x / y

print(divide(7, 0))
Traceback (most recent call last):
  File "demo.py", line 4, in <module>
    print(divide(7, 0))
  File "demo.py", line 2, in divide
    return x / y
ZeroDivisionError: division by zero

课件逐行拆解过这段（Run-time_errors p10–p11）：line 4, in <module> 说明错误从主程序的第 4 行发起；print(divide(7, 0)) 是那一行的代码；line 2, in divide 说明进入了 divide 函数；return x / y 是真正出事的位置；最后 ZeroDivisionError: division by zero 是类型与原因。

「most recent call last」的意思是：越靠下越接近出错点。所以从下往上看调用链、从上往下读代码，是最快的定位方式。

五、try / except：把错误接住

异常处理（exception handling）让程序在出错时不崩，而是转去执行另一段代码（Handling p2）。结构是 try 包住「可能出错的代码」，except 写「出错了怎么办」。

try:
    number = int(input("Give an integer: "))
    print("You gave", number)
except ValueError:
    print("That was not an integer.")

输入 abc 时，int() 抛 ValueError，try 里剩下的语句被跳过，直接进 except，输出提示。输入 42 时正常走完 try，except 不执行。

try 的范围要小：只包住可能出错的那一两行，不要把整个程序塞进去。范围一大，出错时你连是哪一行出的都难判断，还会掩盖本不该被捕获的错误。

六、except Exception as e：拿到异常对象

出错时 Python 会创建一个异常对象，里面装着类型与消息（Handling p4）。用 as e 把它接住就能查看：

try:
    number = int(input("Give an integer: "))
    print("You gave", number)
except Exception as e:
    print(type(e))
    print(e)
    print("Please retry!")

输入 abc，输出：

<class 'ValueError'>
invalid literal for int() with base 10: 'abc'
Please retry!

type(e) 给出异常类，print(e) 给出消息。except Exception 能捕获几乎所有运行时异常，代价是「太宽」——它把你的编程错误也一起吞掉了。初学阶段用它兜底可以，但要知道自己在放弃什么。

七、多个 except：按类型分别处理

Example3 是课件给的完整形态（Handling p6）：一个循环里同时可能出现输入错误、除零、用户中断，三种情况给出三种提示。

while True:
    try:
        x = int(input("Enter an integer: "))
        y = 10 / x
        print(y)
        break
    except ValueError:
        print("Invalid input. Please enter an integer.")
    except ZeroDivisionError:
        print("Division by zero error. Give other number than zero.")
    except KeyboardInterrupt:
        print("User interrupted the program.")
        break

三个要点：顺序——具体的异常写前面，宽泛的（Exception）写后面，否则后面的永远轮不到；只处理你懂的——不知道怎么办就别捕获；KeyboardInterrupt 是用户按 Ctrl+C 触发的，它不像其他异常那样打印完整 traceback。

八、重试循环：让用户有机会改

输入校验的标准形态是「不合法就重来」，直到拿到合法值才 break（Example1、Example2）：

while True:
    try:
        nr = int(input("Enter an integer: "))
        break
    except ValueError:
        print("You did not give an integer, retry!")

print(f"The entered integer is {nr}")

输入 abc 会提示重试；输入 7 才跳出循环。break 必须写在 try 里、而且是「成功之后」——写在 except 里就变成「出错才退出」，正好反了。

九、调试：不靠猜，靠证据

课件列了四种手段（Errors p7），按成本从低到高：

  1. 插入 print：在关键位置打印变量值与「走到这里了」，最快看清执行流
  2. 用调试器（debugger）：IDLE 的 Debug 菜单可以逐行执行、设断点、查看变量
  3. 请别人看代码：换一双眼睛最容易发现「你以为自己写了、其实没写」的部分；也可以让 AI 解释报错
  4. 写小测试（unit testing）：给函数准备几组「输入 → 期望输出」，改完就跑一遍

CodeGrade 的反馈本质上就是第 4 种：它把你的函数用固定输入跑一遍，比较返回值（CG Guide 第 4.2 节）。看到 Expected: 7 / Received: 3，就说明逻辑错了；看到 The function should return a value，就是用了 print 没 return。

十、一个 bug 的完整修复过程

把前面所有工具串起来，看一次真实的排查流程。假设程序要读入年龄并判断是否成年，代码如下：

age = input("Age: ")
if age >= 18:
    print("adult")
else:
    print("minor")

输入 20，程序崩了，报：

Traceback (most recent call last):
  File "demo.py", line 2, in <module>
    if age >= 18:
TypeError: '>=' not supported between instances of 'str' and 'int'
  1. 读最后一行：TypeError，「字符串与整数不能用 >= 比较」
  2. 往上找自己的行：第 2 行，if age >= 18
  3. 回到第 1 行看 age 从哪来：input() 返回字符串
  4. 修：age = int(input("Age: "))
  5. 复测：输入 20 输出 adult，输入 17 输出 minor，输入 abc 观察新的报错

第五步很重要：修完要测边界与异常输入。abc 会让 int() 抛 ValueError，这才是该加 try/except 的地方——而不是一开始就把整个程序包起来。

十一、主动抛异常与收尾工作

两件课件没展开、但读别人代码会遇到的事（拓展，不作为考点）：

def set_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative")
    return age

try:
    set_age(-5)
except ValueError as e:
    print("Rejected:", e)

try:
    print("working")
finally:
    print("cleanup always runs")
Rejected: Age cannot be negative
working
cleanup always runs

raise 让你在「值不合理」时主动报错，比返回一个特殊值更明确；finally 里的代码无论成功还是异常都会执行，适合关文件、释放资源。第 9 讲的 with 本质上就是自动帮你做这件事。

十二、处理异常的原则

不要写裸 exceptexcept: 什么都不写会捕获包括 Ctrl+C 在内的一切，程序看起来「永不报错」，实际问题被藏起来。至少写 except ValueError:，或 except Exception as e: 并打印 e。
不要用异常代替正常判断能先判断就判断：if y != 0: print(x / y) 比「先除再看有没有异常」清楚得多。异常是给「预料之外的失败」用的，不是流程控制。
捕获后要给出路except: pass 等于把错误吞掉。至少打印提示、返回默认值、或让用户重试——否则程序「静默地错」比崩溃更难查。
先让程序崩，再决定捕获调试阶段先不加 try，让 traceback 完整打出来定位问题；确定这类错误在真实使用中会发生（如用户输入），再加 try 并给出友好提示。
推导补充

三类错误排查顺序不同：语法错误运行前拦下，看行号（真错常在报错行上一行）；运行时错误看异常类型与调用栈；逻辑错误不报错，只能靠“输入—期望—实际”对照。traceback 按 most recent call last 排，越靠下越接近出错点：先读最后一行定类型，再往上找自己的行。ValueError 是“类型对、值不对”，TypeError 是“类型就不对”。

常见误解

try 范围要小，只包可能出错的一两行，包住整个程序就掩盖位置。break 要写在 try 里“成功之后”，写进 except 就变成出错才退出。多个 except 要具体在前、宽泛在后。裸 except: 连 Ctrl+C 都吞，except: pass 让程序静默地错。调试阶段先不加 try，让 traceback 打全再决定捕获。

例 1　读入一个整数，输入不合法时提示并重试，直到成功。

用 while True + try + break：成功才跳出，失败留在循环里。

while True:
    try:
        n = int(input("Enter an integer: "))
        break
    except ValueError:
        print("Not an integer, try again.")

print("You entered", n)
print("Its square is", n * n)

交互示例（> 表示用户输入）：

Enter an integer: > abc
Not an integer, try again.
Enter an integer: > 2.5
Not an integer, try again.
Enter an integer: > 12
You entered 12
Its square is 144

解释：int("abc") 与 int("2.5") 都抛 ValueError（第二个是因为字符串本身带小数点，不是整数字面量），所以都被 except 接住。只有 int("12") 成功，执行到 break 跳出。

例 2　对两个输入做除法，分别处理「输入不是整数」与「除数为零」。

两个 except 按类型分开；顺序无关（两者互不包含），但具体类型写在前面是好习惯。

try:
    a = int(input("Dividend: "))
    b = int(input("Divisor: "))
    print("Result:", a / b)
except ValueError:
    print("Both inputs must be integers.")
except ZeroDivisionError:
    print("Cannot divide by zero.")

三种输入的结果：

Dividend: 10   Divisor: 2   ->  Result: 5.0
Dividend: 10   Divisor: 0   ->  Cannot divide by zero.
Dividend: ten  Divisor: 2   ->  Both inputs must be integers.

解释：除数 0 时 a / b 抛 ZeroDivisionError，被第二个 except 接住；输入 ten 时 int() 先抛 ValueError，根本走不到除法。注意 try 里三行是一个整体：任何一行抛异常，后面都不执行。

例 3　读取一个可能不存在的文件，文件缺失时给出提示而不是崩溃。

文件类操作最适合用异常处理：路径由用户给，缺失是常态。

filename = input("File name: ")
try:
    file = open(filename, "r")
    lines = file.readlines()
    file.close()
    print("lines:", len(lines))
except FileNotFoundError:
    print("No such file:", filename)

两种输入的结果：

File name: > Example.txt
lines: 4
File name: > missing.txt
No such file: missing.txt

解释：open 找不到文件时抛 FileNotFoundError（消息里带 Errno 2），被捕获后只打印提示。file.close() 写在 try 里，只有打开成功才会执行——这也说明为什么 try 的范围要恰好包住相关操作。

例 4　下面这段代码哪里错？为什么它永远输出不了「负数」？

题目代码：n = int(input()); if n > 0: print("正"); elif n > 10: print("很大")。

n = int(input("n: "))
if n > 0:
    print("positive")
elif n > 10:
    print("large")

这是逻辑错误，不是语法或运行时错误：n > 10 为真时 n > 0 一定也为真，所以第二个分支永远走不到。程序不报错，只是结果与意图不符。

修正思路：把范围窄的条件放前面，或者用互斥区间写全。这类错误只能靠「拿边界值测一遍」发现：输入 0、1、10、11，看输出是否符合预期。

  1. 下面哪些是语法错误、哪些是运行时错误？①if x > 1 后漏冒号 ②10 / 0 ③int("abc") ④print("a" ⑤len(5)
  2. 写一个函数 safe_int(s)：能转成整数就返回整数，否则返回 None。
  3. 读入两个数做除法，要求：除数为 0 时输出提示、重新输入；输入非数字时也重新输入。
  4. 解释这段代码为什么会崩，并修正：L = [1,2,3]; print(L[3])。
  5. 写一段代码，捕获 IndexError 并从列表中安全地取第 10 个元素（不存在时返回 None）。
答案与思路

1. ①④ 是语法错误（漏冒号、括号未闭合），程序根本跑不起来；②③⑤ 是运行时错误：ZeroDivisionError、ValueError、TypeError（len 不接受整数）。判断标准：能不能通过解释器的语法检查。

2. try: return int(s) / except ValueError: return None。捕获范围要窄，只 catch ValueError；若 catch Exception，连 TypeError（比如传了列表）也会被吞掉，掩盖真正的问题。

3. 两层校验可以放在同一个 try 里：先 int(input()) 两次，再判断除数是否为 0；except ValueError 处理非数字，if b == 0 单独给提示。注意 continue 与循环结构：把「成功」放在最后并 break。

4. 列表长度 3，合法下标 0–2，L[3] 抛 IndexError: list index out of range。修正：取 L[-1] 或判断 if len(L) > 3；如果确实要「不存在就返回 None」，用 try/except IndexError。

5. try: return L[9] / except IndexError: return None。更好的写法是先判断 if len(L) > 9——异常处理适合「意料之外」，长度检查适合「可以预知」的情况。

必考三类错误的区分；常见异常名与触发条件；traceback 的读法（最后一行是异常类型）；try/except 结构与 as e；重试循环的写法。
易错 1　except 顺序把 except Exception 写在最前面，后面所有具体异常都轮不到，提示永远是通用的那句。具体在前、宽泛在后。
易错 2　try 范围过大 / 裸 except把整个程序包进 try，出错时无法定位；except: pass 会把 Ctrl+C 都吞掉。范围要小、类型要具体。
易错 3　break 放错位置重试循环里 break 必须写在 try 成功路径的末尾；写进 except 就变成「一出错就退出」。
进阶raise ValueError("message") 可以主动抛异常；finally 里的代码无论成功失败都会执行（适合关闭文件）；自定义异常类属于后续课程。

操作清单

看到报错时的处理顺序

  1. 先读最后一行：异常类型 + 消息
  2. 再往上找自己文件的行号与函数名
  3. 回到那一行，打印相关变量的值确认状态
  4. 判断是三类中的哪一类：语法 / 运行时 / 逻辑
  5. 修完用同样的输入再跑一次，并补一个边界输入

写异常处理时的检查

  • try 只包住可能出错的那几行
  • except 写具体类型，必要时才用 Exception
  • 捕获后给出了提示或替代结果，没有 pass
  • 重试循环里 break 在成功路径上
  • 调试阶段先不加 try，让 traceback 完整显示
